Реализуй массовое редактирование — фича, ради которой люди используют Коммандер
вместо веб-интерфейса. Тип операции этого запуска: `$1` (если пусто — базовый
фреймворк массовых операций + `status`).

## Общая механика

- Операция применяется к **выделенным строкам** грида (может быть тысячи).
- Каждая операция:
  1. предпросмотр (сколько объектов затронуто, что изменится, оценка баллов);
  2. применение **локально** (меняет строки в БД, `sync_status → modified`),
     БЕЗ немедленной отправки — отправка отдельным Push;
  3. запись в **историю с возможностью Undo** (до синхронизации).
- Валидация через `core/validation` до применения; невалидные строки
  показываются отдельно и не ломают остальные.

## Операции (реализуй по `$1`)

- **status**: массово suspend/resume/archive/unarchive/moderate.
- **bids**: массовое изменение ставок — установить значение, ±процент, по
  стратегии/правилу; для ключевых слов и групп. Учитывай ограничения Директа на
  минимальную ставку.
- **find-replace**: поиск-замена по текстовым полям (заголовки/тексты
  объявлений, ключевые слова), включая режим регулярных выражений и
  предпросмотр диффа.
- **copy**: копирование объектов между группами/кампаниями (объявления,
  ключевые слова) с корректным сбросом `direct_id` (копии = `new`).
- **labels**: массовое проставление/снятие меток.

## Что сделать

1. `BulkOperation` интерфейс: `preview(selection)`, `apply(selection)`, `undo()`.
2. Реестр операций + UI-панель массовых действий в гриде (из `/grid-ui`).
3. История операций с Undo (стек, сбрасывается после успешного Push).
4. Тесты (Vitest): предпросмотр считает верное число; apply переводит строки в
   `modified`; undo откатывает; невалидные строки изолируются.

## Критерии готовности

- Выделив N строк, можно применить операцию и увидеть их `modified`.
- Undo возвращает прежние значения (до Push).
- Оценка баллов показывается в предпросмотре.
