Реализуй импорт и экспорт данных. Аргументы: направление `$1`, формат `$2`
(по умолчанию — оба направления, `xlsx`). Это ключевая фича Коммандера:
редактировать кампании в Excel и заливать обратно.

## Требования

- Форматы: **XLSX** (через `exceljs`) и **CSV**. Кодировки и разделители
  настраиваемые (учитывай Excel-CSV с `;` и BOM для кириллицы).
- **Экспорт**: выгрузка выбранного уровня (кампании / группы / объявления /
  ключевые слова) с колонками, читаемыми человеком; сохранение `direct_id` в
  скрытой/служебной колонке, чтобы обратный импорт мог сопоставить строки.
- **Импорт**:
  - сопоставление строк по `direct_id` (обновление) или его отсутствию
    (создание новых, `sync_status = new`);
  - маппинг колонок файла на поля сущностей с предпросмотром;
  - **валидация** каждой строки через `core/validation` (лимиты длины, статусы,
    обязательные поля) с отчётом об ошибках по строкам ДО записи в БД;
  - импорт меняет только локальную БД; выгрузка в Директ — отдельным Push.
- **Шаблоны**: генерация пустого шаблона XLSX с правильными колонками для каждой
  сущности.

## Что сделать

1. Модуль `src/core/io/` (парсинг/сериализация — без Electron) + IPC для выбора
   файла и запуска в main.
2. Схемы колонок на каждую сущность (единый источник — переиспользуй маппинг из
   `/data-model`).
3. Отчёт об импорте: сколько создано/обновлено/ошибок, скачиваемый лог ошибок.
4. Тесты (Vitest): round-trip export→import не теряет данные; битые строки
   попадают в отчёт, а не в БД; кириллица в CSV читается корректно.

## Критерии готовности

- Экспорт → правка в Excel → импорт корректно обновляет строки по `direct_id`.
- Новые строки без `direct_id` создаются как `new`.
- Ошибочные строки не попадают в БД и видны в отчёте.

Не коммить — покажи пример шаблона колонок и сценарий round-trip.
