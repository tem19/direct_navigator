Покрой тестами область `$1` (если пусто — тесты для последних изменений в рабочем
дереве; определи их через `git status`/`git diff`).

## Уровни

- **Юнит (Vitest)** — для `core`, `direct-api`, `db`, `sync`, `core/io`:
  - клиент API: заголовки, авто-пагинация, парсинг `Units`, разбор ошибок и
    частичного успеха — с замоканным `fetch`;
  - репозитории: поверх **in-memory SQLite**, миграции + CRUD + выборка изменённого;
  - мапперы: round-trip `api→domain→db→domain`;
  - валидация: граничные значения лимитов Директа;
  - sync: инкрементальный pull через `changes`, порядок push, детект конфликтов,
    изоляция частичных ошибок;
  - bulk/io: предпросмотр, undo, round-trip import/export.
- **E2E (Playwright `_electron`)** — критические пользовательские сценарии:
  запуск приложения, pull из **sandbox** (или замоканного API), правка ячейки в
  гриде, массовая операция, push, разрешение конфликта.

## Правила

- Никогда не бей по **боевому** Direct API из тестов — только sandbox или моки.
- Тесты детерминированы (без реальной сети в юнитах, фиксированные фикстуры).
- Для БД используй временную/in-memory базу, чистую на каждый тест.

## Что сделать

1. Допиши недостающие тесты для `$1`, следуя уровням выше.
2. Прогони `npm run test` (и `npm run test:e2e` для e2e-области).
3. Если тесты падают — покажи вывод, кратко диагностируй, предложи фикс. Не
   «зеленить» тесты подгонкой под баги.

Не коммить — покажи, что покрыто, результаты прогона и оставшиеся пробелы.
