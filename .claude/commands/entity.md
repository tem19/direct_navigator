Реализуй полную вертикаль для сущности **`$1`** — «сквозной срез» через все слои,
чтобы её можно было выгрузить, отредактировать локально, увидеть в таблице и
синхронизировать. Если `$1` пусто — спроси, какую сущность делаем, и остановись.

Опирайся на уже существующие слои (не дублируй их): клиент API из `/direct-api`,
схему из `/data-model`, движок из `/sync-engine`, грид из `/grid-ui`.

## Пройди по слоям для `$1`

1. **API** (`src/direct-api/`): типы запроса/ответа и сервисная обёртка
   (`getAll/add/update/delete` + статусные операции, если применимо).
2. **БД** (`src/db/`): новая миграция с таблицей и индексами; репозиторий с
   методами CRUD и «дай изменённое для push». Поля синхро-статуса как в
   `/data-model`.
3. **Core** (`src/core/`): доменный тип + мапперы `api<->db<->domain` +
   валидация под лимиты Директа именно для этой сущности (например, для `ad` —
   длины заголовков/текста; для `keyword` — минус-слова, статус).
4. **Sync**: зарегистрируй сущность в порядке зависимостей движка (родители
   раньше детей), убедись что pull/push её подхватывают.
5. **UI** (`src/renderer/features/<$1>/`): страница со списком в гриде,
   инлайн-редактирование, индикатор `sync_status` в строке, панель массовых
   операций (переиспользуй компоненты из `/grid-ui` и `/bulk-edit`).
6. **IPC**: добавь каналы в `src/preload/contracts.ts` и хендлеры в main, чтобы
   renderer читал/писал только через `window.api`.

## Критерии готовности

- Сущность видна в UI после pull из sandbox.
- Локальная правка меняет `sync_status` на `modified` и уходит на сервер при push.
- Валидация ловит превышение лимитов Директа до отправки.
- Тесты: маппер round-trip (`api→domain→db→domain`), валидация, репозиторий.
