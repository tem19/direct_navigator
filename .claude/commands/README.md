# Команды промптов для разработки direct_navigator

Набор slash-команд Claude Code для пошаговой сборки аналога Директ.Коммандера.
Каждая команда — переиспользуемый промпт с зафиксированными архитектурными
требованиями (стек, границы слоёв, специфика Yandex Direct API v5).

## Как пользоваться

В сессии Claude Code внутри этого репозитория набери `/имя-команды` и, при
необходимости, аргумент. Примеры:

```
/scaffold
/direct-api campaigns
/data-model core
/entity ad
/bulk-edit bids
/plan-feature массовая правка ставок по правилу для ключевых слов
```

## Команды

| Команда | Назначение |
|---|---|
| `/scaffold` | Скелет приложения: Electron + React + TS + SQLite, слои, IPC-мост |
| `/direct-api` | Клиент Yandex Direct API v5: auth, сервисы, units, частичный успех, ретраи |
| `/data-model` | Схема SQLite, миграции, репозитории, синхро-статусы, валидация |
| `/sync-engine` | Движок синхронизации: pull (`changes`), push (порядок, батчи), конфликты, баллы |
| `/entity` | Одна сущность Директа сквозняком через все слои (API→БД→core→UI) |
| `/grid-ui` | Табличный редактор в стиле Коммандера: грид, дерево, инлайн-правка, статусы |
| `/bulk-edit` | Массовые операции: ставки, статусы, поиск-замена, копирование, метки, Undo |
| `/import-export` | Импорт/экспорт XLSX/CSV с сопоставлением по `direct_id` |
| `/tests` | Тесты: Vitest (юнит) + Playwright (e2e для Electron) |
| `/plan-feature` | Архитектурный план новой фичи по слоям (без кода) |

## Рекомендованный порядок

Фундамент (по одному разу):

1. `/scaffold` — каркас и слои.
2. `/direct-api campaigns` — базовый транспорт + первый сервис.
3. `/data-model core` — базовая схема, миграции, репозитории.
4. `/grid-ui` — общий переиспользуемый грид.
5. `/sync-engine full` — движок pull/push.

Дальше итеративно по сущностям и фичам:

6. `/entity campaign` → `/entity adgroup` → `/entity ad` → `/entity keyword` —
   расширяют API/БД/sync/UI под каждую сущность.
7. `/bulk-edit …`, `/import-export …` — по мере надобности.
8. `/tests …` — после каждого значимого шага.

Для крупной новой фичи начинай с `/plan-feature <описание>`, затем выполняй
предложенные шаги профильными командами.

## Общие соглашения (заложены в каждую команду)

- Разработка ведётся против **sandbox** Yandex Direct, не боевого API.
- Границы слоёв строгие (см. `CLAUDE.md`): renderer ↔ main только через IPC;
  `core` без Electron/SQL; SQL только в репозиториях.
- Команды **не коммитят** сами — показывают изменения для проверки.
- Секреты только в `.env`.
