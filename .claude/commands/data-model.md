Спроектируй/расширь локальную модель данных в `src/db/` и доменные типы в
`src/core/`. Фокус запуска: `$1` (если пусто — базовая схема `core`).

## Принципы

- SQLite — **источник правды для офлайн-работы**. Пользователь редактирует
  локально, потом синхронизирует. Значит модель должна хранить И серверное
  состояние, И локальные правки, И статус синхронизации.
- Иерархия сущностей Директа:
  `Client → Campaign → AdGroup → (Ad, Keyword, Bid/KeywordBid, AudienceTarget)`.
- У каждой синхронизируемой строки:
  - `direct_id` (ID в Яндекс Директе, `NULL` пока не выгружен),
  - `local_id` (свой автоинкремент / uuid),
  - `sync_status`: `synced | new | modified | deleted | conflict`,
  - `server_hash` / снимок серверных полей — для детекта конфликтов,
  - `updated_at_local`, `synced_at`.
- Мягкое удаление: `deleted` помечается флагом, физически удаляется после push.

## Что сделать

1. **Миграции**: система версионированных миграций (папка `src/db/migrations`,
   таблица `schema_version`, применение по возрастанию при старте main). Никаких
   разрушающих правок существующих миграций — только новые.
2. **Схема** для `$1`: таблицы с индексами по `direct_id`, по внешним ключам
   (campaign_id, adgroup_id) и по `sync_status`. Внешние ключи включены
   (`PRAGMA foreign_keys = ON`).
3. **Доменные типы** в `src/core/`: чистые TS-типы сущностей + мапперы
   `apiRow <-> dbRow <-> domain`. Ни Electron, ни SQL не протекают в `core`.
4. **Репозитории** (`src/db/repositories/`): CRUD + запросы «дай все изменённые
   строки для push», «применить серверный ответ», «пометить synced». Репозитории
   — единственный код, знающий SQL.
5. **Валидация** доменных объектов (лимиты Директа: длины заголовков/текстов,
   допустимые статусы, обязательные поля) в `src/core/validation/`.
6. Тесты (Vitest) на репозитории поверх in-memory SQLite: миграции применяются,
   CRUD работает, выборка изменённого корректна.

## Критерии готовности

- Свежая БД поднимается прогоном всех миграций.
- Можно записать «новую» сущность, изменить её, и репозиторий вернёт её в списке
  на push с правильным `sync_status`.
- `core` не импортирует `better-sqlite3`/`electron`.

Не коммить — покажи схему (DDL) и публичный интерфейс репозиториев.
